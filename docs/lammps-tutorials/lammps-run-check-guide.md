# LAMMPS 运行后独立检查指南

> 这是首次试迁移页面。原始 Markdown 文件保持不变；网页版本仅移除了本机绝对路径。

## 1. 这份指南解决什么问题

运行结束、终端重新出现提示符，只能说明进程已经退出，不能单独证明模拟成功。

独立检查一次 LAMMPS 运行，需要依次回答四个层次的问题：

1. **程序是否完整运行？**
2. **数值计算是否出现明显异常？**
3. **结果是否符合这个模型的物理预期？**
4. **采样是否足以支持科研结论？**

前两项的大部分检查可以跨教程复用；后两项必须结合具体 input 文件、模型和研究问题判断。

---

## 2. 最重要的方法：运行前先写“预期清单”

不要先运行、再漫无目的地翻日志。运行前先从 input 文件中找出以下信息：

| 需要预测的内容 | 通常从哪些命令寻找 |
|---|---|
| 从什么状态开始 | `read_data`、`read_restart`、`create_atoms` |
| 做了哪些阶段 | `minimize`、`run` |
| 最终应到第几步 | `reset_timestep`、`run` |
| 时间步长和模拟时长 | `timestep`、`run` |
| 热力学量多久输出一次 | `thermo`、`thermo_style` |
| 会生成哪些轨迹 | `dump` |
| 轨迹多久输出一帧 | `dump` 的间隔参数 |
| 最后保存什么状态 | `write_data`、`write_restart` |
| 温度或压力目标 | `fix nvt`、`fix npt`、`fix langevin` 等 |
| 原子数是否应该变化 | `create_atoms`、`delete_atoms`、反应或沉积命令 |

每个阶段都先填写：

```text
阶段名称：
输入文件：
读取的上游文件：
主要操作：
预期最终步数：
时间步长：
预期模拟时间：
预期输出文件：
轨迹输出间隔：
预期轨迹帧数：
预期原子数：
目标温度/压力：
本阶段特有风险：
```

如果这些问题还答不出来，说明此时最需要做的是阅读 input，而不是立即运行。

## 3. 通用检查一：程序是否完整运行

检查工具不需要统一。能直观看懂的内容，优先使用最方便的软件：

- 用 Xftp 看文件是否生成、文件大小和修改时间；
- 用文本编辑器直接看 Run-info、Data 文件头和 Log 的最终步；
- 用 OVITO 看帧数、最后时间步和结构；
- 对不熟悉的错误、警告和数值趋势，让 Codex 读取完整文件并解释；
- 只有文件尚未下载或需要快速筛选时，才使用命令行提取信息。

重点是获得可靠证据并理解证据，不是为了使用命令而使用命令。

### 3.1 查看退出码

如果运行脚本生成了 `run-info-阶段名.txt`：

```bash
cat run-info-阶段名.txt
```

重点检查：

- `exit_code=0`：程序正常退出；
- MPI 进程数和 OMP 线程数是否符合计划；
- 工作目录和 LAMMPS 程序路径是否正确；
- 开始、结束时间和耗时是否合理。

Run-info 可以看作“本次运行的身份证和最低层健康检查”。以下情况需要调查：

| 现象 | 可能的问题 |
|---|---|
| 文件没有生成 | 脚本可能在记录开始前失败 |
| 有 `start`，但没有 `end` 或 `exit_code` | 运行可能被强制终止，或脚本没有执行到结尾 |
| `exit_code` 不等于 0 | LAMMPS 或 MPI 异常退出 |
| 工作目录、主机或 LAMMPS 路径错误 | 可能使用了错误的输入、目录或软件安装 |
| MPI/OMP 数量不符合计划 | 运行配置不符合预期 |
| 耗时与阶段规模明显不符 | 可能没有真正执行预期步数 |

`exit_code=0` 是必要条件，但不是充分条件。输入可能只运行了 0 步，或者产生了不合理但有限的数值。

### 3.2 检查预期输出是否存在

优先在 Xftp 中直接检查。需要在终端中检查时才使用：

```bash
ls -lh 预期文件1 预期文件2 预期文件3
```

需要确认：

- 文件存在；
- 文件大小不是 0；
- 修改时间属于本次运行；
- 文件名与下一个阶段的 `read_data` 或 `read_restart` 完全对应。

### 3.3 检查是否到达预期最终步数

可以直接在 Log 中找到热力学表的最后一行。文件过长、需要提取后发送时，再设置文件名和预期步数：

```bash
check_log=log-阶段名.lammps
check_expected_step=预期最终步数
```

然后查找最终步：

```bash
grep -E "^[[:space:]]*${check_expected_step}[[:space:]]" "${check_log}"
```

有对应热力学数据行，才能证明日志记录到了预期步骤。需要同时结合日志结尾确认它不是其他表格中碰巧相同的数字。

## 4. 通用检查二：有没有明显的错误或数值异常

这是最适合由 Codex 辅助的部分。优先把完整 Log 下载到电脑并提供路径；如果文件只在已授权的服务器目录中，则提供服务器目录，让 Codex直接读取和检查。下面的命令是无法直接读取完整文件时的备用筛选方法。

设置日志文件名：

```bash
check_log=log-阶段名.lammps
```

搜索常见异常：

```bash
grep -Ei 'ERROR|WARNING|NaN|Lost atoms|Dangerous builds' "${check_log}"
```

判断方法：

| 日志内容 | 一般含义 | 应采取的行动 |
|---|---|---|
| `ERROR` | LAMMPS 发现致命问题 | 不能继续，先定位错误 |
| `NaN` 或 `Inf` | 数值发散或非法计算 | 通常不能接受，检查初始结构、时间步长和势函数 |
| `Lost atoms` | 原子丢失或离开非周期边界 | 通常是严重问题，检查结构、边界、时间步长和动力学稳定性 |
| `WARNING` | 潜在风险或特殊处理 | 逐条解释，不能看到警告就判失败，也不能忽略 |
| `Dangerous builds > 0` | 邻居表重建可能不够及时 | 需要检查数量、体系运动和邻居表设置 |
| `Dangerous builds = 0` | 没发现危险邻居表重建 | 是良好信号，但不能单独证明物理正确 |

还要观察热力学表中的温度、能量、压力等数值是否始终为有限数值，有没有突然增大许多个数量级。

关键词必须结合上下文。例如热力学数据中的 `Inf` 可能代表数值异常，但 `region block INF ...` 中的 `INF` 是合法的区域边界写法。自动搜索负责发现可疑位置，人负责解释含义。

如果阶段包含 `minimize`，还必须查找 `Minimization stats`：

- 因能量或力容差停止：达到 input 规定的收敛条件；
- 因 `max iterations` 或 `max force evaluations` 停止：命令正常结束，但没有达到能量/力收敛条件；
- 需要结合能量、力降低程度和后续动力学稳定性，区分“严格收敛”“可用的预松弛”和“明显失败”。

## 5. 通用检查三：Data 文件和原子数

如果阶段生成了 Data 文件，可以直接打开文件并查看开头的 `atoms`、`bonds`、`angles` 和类型数量。需要快速提取时才使用：

```bash
check_data=阶段名.data
grep -m1 ' atoms' "${check_data}"
```

把结果与运行前预测的原子数比较。

- 普通 NVE、NVT、NPT 和能量最小化通常不会改变原子数；
- `create_atoms`、`delete_atoms`、沉积、蒸发和某些反应模型可能改变原子数；
- 原子数没变不代表结构一定合理，它只完成了一项一致性检查。

Data 文件主要用于向下一阶段传递盒子、原子状态和拓扑。它不是用于播放动画的轨迹文件。

## 6. 通用检查四：轨迹是否完整

优先在 OVITO 中检查总帧数、第一/最后时间步、每帧粒子数和结构。OVITO 的 `0 / 120` 表示帧编号从 0 到 120，即共有 121 帧，而不是 120 帧。

文件尚未打开或需要批量验证时，才设置轨迹文件名：

```bash
check_traj=trajectory-阶段名.lammpstrj
```

统计帧数：

```bash
grep -c '^ITEM: TIMESTEP' "${check_traj}"
```

查看第一帧和最后一帧的时间步：

```bash
awk '/^ITEM: TIMESTEP/{getline; if (first=="") first=$0; last=$0} END{print "first_step=" first; print "last_step=" last}' "${check_traj}"
```

检查轨迹包含的原子属性：

```bash
grep -m1 '^ITEM: ATOMS' "${check_traj}"
```

如果一次运行从第 0 步开始，每隔 `N` 步输出一帧，并且最终步正好能被 `N` 整除，常见的预期帧数是：

```text
帧数 = 最终步数 / 输出间隔 + 1
```

加 1 是因为通常还包含第 0 步。这个公式不是无条件成立：`reset_timestep`、续算、追加轨迹或特殊 dump 设置都可能改变结果，因此必须先阅读 input。

需要区分“间隔数量”和“采样点数量”。例如从 0 到 30000、每 250 步一次，共有 120 个间隔和 121 个采样点。

轨迹通过文件检查后，还要在 OVITO 中观察：

- 模拟盒和边界是否正确；
- 原子类型和元素映射是否正确；
- 有没有明显飞散、重叠或异常空洞；
- 分子是否看起来完整；
- 动态阶段是否存在不合理的剧烈运动。

## 7. 哪些判断不能完全通用

下面的问题没有一条适用于所有模拟的固定阈值：

- 温度必须离目标温度多近；
- 压力波动多大才合理；
- 势能应该是多少；
- 平衡需要多长时间；
- 密度、速度剖面、黏度等结果是否正确；
- 一条轨迹是否已经具有足够的统计独立性。

这些判断需要结合：

1. 系综和温控/压控方法；
2. 体系大小、组成和边界；
3. 力场及单位制；
4. 时间序列而不是单个最终值；
5. 文献、理论值或可靠参考结果；
6. 更长时间、重复模拟和参数敏感性测试。

因此必须区分：

| 结论层次 | 能说明什么 |
|---|---|
| 程序成功运行 | 命令执行完，文件生成，没有明显致命错误 |
| 数值过程基本正常 | 没有发散、丢原子等明显异常 |
| 定性趋势合理 | 结构或曲线方向符合物理预期 |
| 定量结果一致 | 与参考值在约定误差内一致 |
| 科研上已经收敛 | 对时间、初值、体系大小和参数变化具有充分可靠性 |

不能从前一个层次自动跳到后一个层次。

## 8. 教程 4 Equilibrate 阶段示例

从 `equilibrate.lmp` 可以在运行前预测：

```text
阶段名称：equilibrate
读取的上游文件：create.data
主要操作：先能量最小化，再做 NVT 平衡
重置后的起始步：0
NVT 最终步数：30000
时间步长：1 fs
NVT 模拟时间：30000 fs = 30 ps
目标温度：300 K
预期原子数：1680
最终状态文件：equilibrate.data
最小化轨迹：trajectory-equilibrate-minimize.lammpstrj
NVT 轨迹：trajectory-equilibrate.lammpstrj
NVT 轨迹间隔：250 步
常见预期 NVT 帧数：30000 / 250 + 1 = 121 帧
```

本次实际检查还得到：

```text
最小化：508 次迭代，1001 次力/能量计算
停止原因：达到最大力计算次数，并未达到能量或力收敛容差
最小化轨迹：7 帧，时间步为 0、100、200、300、400、500、508
NVT 轨迹：121 帧，时间步为 0 到 30000，间隔 250
每帧原子记录：1680，未发现残缺帧
致命错误：未发现 ERROR、NaN、Lost atoms、MPI 崩溃或缺失键原子
温度：前期从 0 K 升温，后期分段平均温度接近 300 K
墙间距：在 30 ps 内仍呈下降趋势，尚不能证明结构量已经形成稳定平台
```

这里必须区分：

```text
LAMMPS 正常完成 minimize 命令
不等于
最小化达到能量或力收敛条件
```

达到 `maxeval` 是 LAMMPS 允许的正常停止条件，所以 input 会继续执行后续 NVT；但检查结论必须明确记录“严格最小化未收敛”。本次能量和力显著降低，后续 NVT 又稳定完成，因此它可以作为教学流程中的预松弛状态继续使用，不能作为科研意义上充分收敛的证明。

本阶段的最低技术通过条件是：

- `exit_code=0`；
- 日志到达第 30000 步；
- 没有 `ERROR`、`NaN` 或 `Lost atoms`；
- `equilibrate.data` 存在并仍包含 1680 个原子；
- NVT 轨迹的第一步、最后一步和帧数符合 input 设置；
- 轨迹能在 OVITO 中打开并且结构没有明显异常。

即使全部满足，也只能说明教学用平衡阶段技术上完成、没有明显异常。30 ps 是否足以支持科研结论，还需要检查温度、能量和结构随时间的变化，并进行更长模拟或重复测试。

## 9. 推荐的学习方式

以后每个阶段采用下面的顺序：

1. **你先阅读 input，填写预期清单。**
2. **你用 Xftp、Log、Data 和 OVITO 检查自己能理解的内容。**
3. **你把预期和已经理解的观察结果告诉 Codex。**
4. **Codex 自动读取本机或已授权服务器中的完整输入、Log 和必要输出，检查错误、警告、数值异常和趋势。**
5. **Codex 对每条重要信息说明：看到了什么、代表什么、这次怎样判断、以后遇到同类信息怎样判断。**
6. **Codex 通过少量理解问题确认判断方法是否已经掌握，而不只给出验收结论。**
7. **你先尝试给出分层结论，Codex 再纠正和补充。**
8. **最后决定是否进入下一阶段，以及哪些问题留到统计可靠性和科研收敛阶段。**

目标不是记住所有 Linux 命令，而是形成固定思路：

```text
先预测 → 再运行 → 查证据 → 作解释 → 分层下结论
```

命令只是取得证据的工具，不要求为了学习而机械使用命令。能够独立提出正确的问题、选择合适的查看方式并解释证据，才是真正学会了检查模拟。

## 10. 每次如何启动这套检查流程

在当前对话中，可以直接说：

```text
请按 LAMMPS 运行后独立检查指南，开始检查“阶段名称”。
```

如果是新对话，请同时提供本指南的 Markdown 文件或网页链接。

推荐复制并填写下面的启动模板：

```text
请按 LAMMPS 运行后独立检查指南，开始本阶段检查。

阶段名称：
本阶段 input 文件：
服务器运行目录：
本机结果目录：

我的运行前预期：
- 读取的上游文件：
- 主要操作：
- 预期最终步数：
- 时间步长和模拟时间：
- 预期输出文件：
- thermo 间隔：
- dump 间隔和预期帧数：
- 预期原子数：
- 目标温度/压力或其他控制量：

我已经能理解并检查的信息：
-

我暂时不理解的信息：
-

请你自动读取本机或已授权服务器中的必要文件。对每项发现都告诉我：
1. 看到了什么；
2. 它代表什么；
3. 这次应该怎样判断；
4. 以后遇到同类信息怎样判断。
最后请让我先尝试作出分层结论，再纠正我，并明确是否可以进入下一阶段。
```

启动后，Codex 应固定按以下顺序工作：

1. 核对运行前预期是否与 input 一致；
2. 核对用户通过 Xftp、Log、Data 和 OVITO 得到的直观观察；
3. 自动检查完整文件中的错误、警告、停止原因、数值异常和时间趋势；
4. 用“证据—含义—本次判断—通用判断方法”的格式讲解；
5. 区分程序完成、数值稳定、定性合理、定量一致和科研收敛；
6. 通过理解问题让用户先作结论；
7. 给出本阶段结论和下一阶段是否可以开始。

不需要把完整 Log 粘贴到对话中。只要提供准确的本机路径或已授权服务器目录，Codex 应优先直接读取原始文件。
